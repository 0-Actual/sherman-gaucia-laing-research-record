## Integrity and reproducibility

Download this edition directory with its manifest and archives. Using Python 3.10 or newer, run `python -B verify_release.py` in a clean copy of the directory. For a separately trusted manifest reference, add `--manifest-sha256 EXPECTED_SHA256`. The verifier reads files and archive members; it does not execute research programs or extract archives.

Each archive has a `RELEASE_CONTENT_MANIFEST.json` for the bytes distributed now. Original manifests and receipts remain dated historical evidence. Original verification scripts may reject added release notices or sanitized files; use the new release verifier for this distribution. Read the separate scientific reproduction instructions for each experiment and its actual inputs/dependencies.

The revised verifier passed fifteen targeted valid/tampered-input checks. The service correction passed 55 isolated tests; see the revision review for scope. Archive members were read back during assembly. Existing scientific checks are retained rather than represented as new runs. A hash is an integrity reference; a GitHub verified commit is a separate signature fact. Neither proves scientific validity, original authorship, conception date or institutional use.
