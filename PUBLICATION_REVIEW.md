# Publication review requirements

Owner: Sherman Gaucia Laing. Maintainer: GAUCIA through ChatGPT/Codex. Recorded 18 September 2026 UTC following the owner's instruction to complete the agreed study before publishing dataset statements.

## Required before publication

1. Record the exact source version, scope, record count, license, and attribution. State what was acquired and what remains a link or unexamined source.
2. Finish the agreed review scope. For a complete acquired-dataset study, examine all fields and records, nested values, missingness, duplicates, numerical validity and relevant source methods. Do not describe a narrow census as comprehensive physical validation.
3. Separate measured observations, supported interpretations, and unresolved causes. Test reasonable representational explanations before presenting metadata differences as scientific errors. Preserve original values.
4. Check units, normalization, calculation method, cohort selection and historical-version limits. Missing is not zero; finite is not necessarily physically credible.
5. Record the actual program, version or preserved source, input, settings and outputs for any execution claim. Identify GAUCIA's project role separately from the executable. State whether a QEL simulator/emulator was actually invoked; a reference implementation must not be mislabeled as it.
6. Retain the performed validation and replay results, including failures and metric scope. Agree on a numerical acceptance condition before a test; do not invent certification or generalize a narrow result to the whole project.
7. Review the exact public file selection, factual consistency, source citations and disclosure boundaries. Keep withheld code, private interactions, personal records, signing keys and unrelated research out of the selection.
8. Preserve a dated audit record, file inventory and available measurements. Verify the published files against the reviewed selection and retain a recoverable owner copy. Do not manufacture a signature; signed releases require the owner's actual authorized signing process.

## Preliminary records and updates

Publication of preliminary work requires explicit owner authorization and a prominent scope/unfinished-review label. Otherwise, complete the agreed review before publication. If a source or interpretation changes, add a dated clarification that distinguishes retained observations from changed interpretations; link it from the earlier landing page. Preserve historical commits and original measurement records.

This is a documented maintainer procedure. It is not a claim that GitHub branch protection or automated enforcement has been installed. It cannot guarantee that later scientific evidence will never justify an update. The scope of routine maintenance, owner decisions and actual scheduling remains in [MAINTENANCE.md](MAINTENANCE.md).
